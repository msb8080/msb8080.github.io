# AI Composer Blog 90 天优化路线图（Astro 执行版）

## 目标定义（North Star）

在 90 天内，把博客从“可发布”升级为“可持续增长的内容系统”：

- 工程上：Astro 构建稳定、URL 可回归、发布可验证
- 内容上：聚焦模型接入、Agent/Harness 与 AI 后端工程

## 2026-09-05 落地基线

- 已完成 Astro 静态迁移、历史 URL 保持、首页视觉与移动端适配。
- 已完成 Harness 独立系列页、同系列前后篇、相关推荐和搜索交互。
- 已完成结构化数据、社交分享卡、更新时间/核验时间与基础无障碍增强。
- 已完成构建产物全量引用检查和发布后线上冒烟检查。
- 待外部处理：GitHub 账户级 Actions 恢复后，仓库工作流即可自动执行同一套门禁。

## 阶段一：Day 1-30（打基础，控范围）

### 目标

- 修复体验断点
- 提升内容供给质量
- 降低维护认知成本

### 关键动作

1. 导航一致性修复
   - 检查菜单链接与实际页面是否一一对应
   - 缺失页面立即补齐或暂时下线入口
2. 赛道聚焦
   - 主线锁定：AI 后端 + Agent/Harness + 工程化评测
   - 不新增 RAG 工程开发系列；已有 RAG 文章仅作为历史知识保留
   - 副线降频：投资理财/副业探索
3. 代表作冲刺（3~5 篇）
   - 每篇必须有“问题-方案-执行-复盘”
4. README 建立
   - 根目录单入口说明：启动、写作、发布、文档索引
5. 文档口径统一
   - 统一 Node、发布流程、分支策略表述

### 里程碑（M1）

- 首页无无效入口
- 主线至少 3 篇正式内容上线
- README 完成并可指导新机器快速启动

---

## 阶段二：Day 31-60（强流程，上自动化）

### 目标

- 把“靠人记忆”改成“靠流程保障”
- 把“本机可用”改成“仓库级可用”

### 关键动作

1. CI 构建校验
   - 自动执行 `npm ci`、类型诊断与 Astro build
   - PR 或 push 即触发
2. 发布边界治理
   - 统一 `dist/` 产物，只更新 Pages 仓库 `/blog/` 子目录
3. 校验范围扩展
   - 从“最新文章”升级到“变更文章集”或“全量扫描”
4. 系列化阅读
   - 完善 Agent Harness 系列导航，建立模型雷达与 AI 后端专题入口

### 里程碑（M2）

- 本地检查稳定发现构建问题；账户级 Actions 恢复后启用同一门禁
- 校验规则覆盖多文场景
- 主线内容具备“入口页 + 连载页”结构

---

## 阶段三：Day 61-90（做闭环，看数据）

### 目标

- 形成“发布-反馈-复盘-迭代”的闭环

### 关键动作

1. 季度复盘实战
   - 使用现有模板完成首次真实季度复盘
2. 指标看板最小化
   - 记录发文数、主线占比、互链率、更新率、Top 文章
3. 内容复用机制
   - 把高质量文章拆分为：清单版/问答版/复盘版
4. 下季度计划制定
   - 保留有效动作，淘汰低收益动作

### 里程碑（M3）

- 完成一轮季度复盘并产出可执行下季度计划
- 主线内容形成持续更新惯性
- 工程发布路径可迁移、可追溯、可验证

---

## 风险与预案

1. 风险：选题过宽导致执行分散  
   预案：坚持“主线优先”周计划，副线仅补位。
2. 风险：自动化投入过重拖慢发文  
   预案：先做最小 CI（构建校验），部署自动化后置。
3. 风险：复盘流于形式  
   预案：每次复盘必须输出“3个保留动作 + 3个淘汰动作”。

---

## 每周节奏（建议）

- 周一：选题确认（1 主线 + 1 储备）
- 周三：首稿完成（结构先行）
- 周五：校验发布（check/preview/release）
- 周末：数据记录与下周调整
